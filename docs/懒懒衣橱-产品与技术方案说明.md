# 懒懒衣橱 · 产品与技术方案说明

> 文档目的：面向客户/合作方，说明产品功能构成与各功能点的技术实现方式，供技术评审与答疑使用。
> 文档版本：v1.0（2026-09-10）

---

## 1. 产品概述

**懒懒衣橱**是一款基于微信小程序生态的 AI 衣橱管理与穿搭推荐产品。核心闭环：

> 拍照上传衣物 → AI 自动建档 → 结合实时天气 / 个人身材画像 / 韩系灵感案例库，
> 每日生成 3 套可直接出门的穿搭方案 → AI 演绎上身效果图 → 一键收藏与保存。

产品差异点：**推荐不是泛泛的"通用穿搭建议"，而是落到用户自己的衣柜、可溯源到具体灵感案例的可执行方案**；上身效果图优先使用用户衣橱中的真实衣物图像。

## 2. 技术架构

### 2.1 技术栈总览

| 层级 | 技术选型 | 说明 |
|---|---|---|
| 前端 | 微信小程序（原生框架） | 4 个主页面 + 若干子页面， tabBar 直达 |
| 后端 | 微信云开发 | 云函数（Serverless）+ 云数据库 + 云存储，免运维 |
| 生成式图像 | 阿里云百炼 `qwen-image-3.0` | 多图融合图生图（人物底图 + 服装平拍图进模型） |
| 视觉理解 | Qwen3-VL（经 SiliconFlow 托管） | 单品平拍图 → 结构化属性 + 细节描述 |
| 推荐语言模型 | DeepSeek 系列（SiliconFlow）+ 腾讯云开发 AI+ | **双供应商自动降级**，主通道故障无缝切换 |
| 实时天气 | 高德开放平台 Web 服务 API | 按定位获取实时气温与天气现象 |
| 商品抠图 | 腾讯云数据万象 GoodsMatting | 真实 AI 抠图，输出带透明通道的高精度 PNG |

### 2.2 架构设计原则

1. **单一数据真源**：所有图片资产统一存放于微信云存储（fileID 寻址），外部 AI 服务直接消费云存储临时链接，图片不落地、不迁移。
2. **Serverless 无状态**：业务逻辑全部收敛在 7 个云函数中，按需触发、按量计费，无闲置成本。
3. **密钥零前端暴露**：所有第三方 API Key 均配置在云函数环境变量中，小程序端不可见。
4. **按需生成**：图像生成仅由用户主动点击触发并命中缓存体系，不预生成、不浪费。

## 4. 各功能点实现说明

### 4.1 批量单品上传流水线

**实现方式**：页面仅承担选图/上传/调用云函数等 IO 操作，全流程状态机（待上传 → 上传中 → 抠图中 → 识别中 → 预览确认）收敛为独立纯函数模块，可离线自动化测试。

**关键设计**：

- 串行队列逐张流转，**任一环节失败均有退路**：上传失败可跳过、抠图失败可用原图继续、识别失败可手动填写——任何单点故障不会锁死批次；
- 并发保护采用**代次令牌**机制：用户重试/跳过后，旧的轮询循环全部作废，杜绝重复回调与假弹窗。

### 4.2 AI 商品抠图

**实现方式**：调用腾讯云数据万象 GoodsMatting 接口，采用 `detect-url` 模式——图片以云存储临时链接形式参与处理，**原图不出微信云存储体系**；输出带 alpha 透明通道的高精度 PNG 回存云存储。

**关键设计**：

- 相比传统色键算法（取边缘背景色 + 颜色距离阈值），真模型抠图在渐变背景、阴影、复杂杂物场景下边缘干净、衣物本身零损伤；
- 同步接口封装 start/poll 外壳 + 客户端超时保护，失败按错误类别分流（欠费/未开通/签名/限流/图像问题），**只有可重试的错误才引导重试**。

### 4.3 AI 商品识别与结构化建档

**实现方式**：视觉语言模型（Qwen3-VL）读取抠图后的平拍图，按固定输出契约生成结构化 JSON：品类、颜色、材质、季节标签、版型标签、细节描述（磨白/印花/五金等）。识别结果进入**预览确认页**，用户核对/修改后手动点击"确认入库"。

**关键设计**：

- **AI 永不自动写库**：识别结果只进预览，入库动作必须由用户确认——AI 可以预填，但"这件衣服进衣橱"的决定权在人；
- **词表归一化**：版型（fit）按品类路由到各自的标签体系（内搭按宽紧+长短、长裤按版型+长短、鞋先分鞋型），自由文本先归一化再入库，杜绝脏数据；
- 识别细节描述（desc）按单品缓存，一次读图终身复用，不重复消耗调用量。

### 4.4 个人穿搭档案

**实现方式**：用户录入身高/体重/肩型/肤色/穿搭雷区/偏好，编码为推荐引擎的结构化画像参数；同时管理"演绎模特参考照"及其类型标记。

**关键设计**：

- 参考照按类型分流：**自拍不进生成画面**（fail-closed 策略——宁可禁错，不可漏放），演绎统一使用用户上传的身材相近的模特底图；
- 档案读取带**自愈收敛**：按用户身份收敛到本人唯一文档，优先取含新字段的记录，历史冗余文档自动降权，避免旧数据劫持。

### 4.5 天气驱动的推荐引擎

**实现方式**：高德 API 获取用户定位实时气温 → 映射到 **5 档温度档** → 每档定义允许的季节标签、外套保暖度规则、禁短袖规则 → 对衣橱执行三层前置过滤（袖长闸门 → 外套保暖度逻辑 → 基础季节标签）。

**关键设计**：

- **温度驱动而非日历驱动**：9 月气温 30℃ 时绝不会推荐毛绒开衫——不合时宜的单品在进入推荐模型前就被代码过滤，模型"根本看不见"，而非"被要求别用"；
- 过滤后衣橱为空时诚实放宽为"全量 + 温度提示"，**宁可放宽也不返回空方案**。

### 4.6 韩系灵感案例库与推荐溯源

**实现方式**：维护结构化灵感案例库（每条含：单品结构 / 配色逻辑 / 身材迁移分析 / **硬约束公式**）。推荐时案例经**双闸筛选**注入提示词：

- 闸 1 季节交集：案例季节与当日温度档允许季节按字符级交集匹配；
- 闸 2 约束可满足性：案例的硬约束公式必须能在用户当前衣橱中真正凑齐，凑不齐的案例不注入。

**关键设计——推荐溯源（防 AI 编造）**：

- AI 返回的每套方案自报灵感来源 id，系统做**四态判定**：`满足（verified）`/ `不满足（降级）` / `编造（降级）` / `诚实声明无参考（合法）`；
- 判定以**结构满足为主闸**——生成的搭配必须真的穿出了该案例的硬约束公式（如"oversize 外套 ×1 + 修身内搭 ×1"）才能署名，文本相似度只作次级排序；
- 不满足时自动映射其他满足约束的案例，仍无则诚实降级，**绝不硬凑署名**；
- 案例库实行三级验真准入（一手内容入库 / 二手转载须标注原出处 / 多级改写稿拒收），案例库存量与构成随响应回传前端，构成可被用户直接验收。

### 4.7 AI 推荐生成（三套结构契约）

**实现方式**：提示词组装（规则 + 案例 grounding + 画像）→ LLM 生成 3 套 JSON 方案 → 解析与多层校验。

**关键设计**：

- **结构契约**：第 1 套固定为"今天就能穿"（100% 来自用户衣橱、零种草），第 2/3 套允许加入 1–2 件"种草单品"作灵感补充；
- **多层兜底**：单品 id 逐一对照安全候选池（幻觉 id 直接丢弃）、第 1 套纯衣橱契约由代码强制保证、LLM 输出 JSON 解析失败自动重试；
- **双供应商降级**：主通道 SiliconFlow 故障时自动切换腾讯云开发 AI+，推荐链路不因单一外部服务中断。

### 4.8 AI 演绎上身效果图

**实现方式**：采用多图融合图生图（qwen-image-3.0）：**人物模特底图 + 上装平拍图 + 下装平拍图**三张真实图像直接输入模型，配合结构化穿搭指令（穿着顺序、叠穿层次、版型锚定、配饰佩戴位置），生成整套搭配的上身效果图。

**关键设计**：

- **真实衣物进模型**：上装/下装以平拍图为参考参与生成（非纯文字描述），版型与颜色的还原度显著高于纯文生图；每件衣物的 VLM 细节描述（磨白/印花/五金）进一步辅助还原；
- **组合缓存**：缓存键由"单品集合 + 场景 + 提示词版本 + 画面输入指纹 + 模型标识"组合而成——任一影响画面的输入变化（换单品图、换模特图、换模型）自动产生新键，杜绝"改了配置却看到旧图"；
- **诚实标注**：效果图明确标注"AI 演绎 · 非本人试穿"；
- **能力边界（如实告知）**：图像模型参考图上限为 3 张，人物与上下装占满；帽/鞋/包等配饰通过文字指令参与生成，出现具有概率性。结构性升级方案（分两趟生成：先人衣主体、再叠加配饰参考图）已在迭代规划中。

### 4.9 收藏与图片导出

**实现方式**：方案一键收藏（含效果图与溯源信息）至"我的收藏"；效果图保存到相册走"下载临时文件 → 写入相册"标准两段式调用。

**关键设计**：保存失败按原因**分类提示**——小程序后台未声明相册权限（引导后台配置）与用户历史拒绝授权（引导设置页打开）是两类完全不同的解法，分别给出对应的下一步操作，并透出原始错误信息便于定位。

### 4.10 额度与成本控制

**实现方式**：图像生成实行**月度额度闸**（按北京时间判定自然月），超出额度友好提示而非报错；缓存命中不扣额度。

## 5. 关键工程设计

| 设计 | 说明 |
|---|---|
| 组合缓存体系 | 所有生成结果按"输入即键"原则缓存，相同输入零成本复用；调试期换图自动失效重出，保证所见即所配 |
| 多级降级链 | LLM 双供应商、案例库多级加载（内存 → 远端 → 随包保底 → 内置兜底）、识别失败手填写——任一外部依赖故障都有退路 |
| 结果自证 | 云函数在响应中回传实际使用的模型、实际取用的档案值、部署版本号等自证字段，前端可判定"配置是否生效"，故障可定位到环节 |
| 质量保障 | 全链路 30+ 个离线自动化测试门（node 直跑，秒级红绿反馈），核心状态机与纯逻辑全部单测覆盖；重要改动经双轴代码评审（标准符合性 + 规格符合性） |
| 版本管理 | 提示词与部署版本带版本盐，改动即换缓存键；云函数版本与前端校验值配对，部署遗漏可被系统主动发现 |

## 7. 安全设计

- **密钥管理**：高德、SiliconFlow、百炼、腾讯云等全部密钥仅存于云函数环境变量，小程序端与代码仓库均不出现明文；
- **数据权限**：云数据库"仅创建者可读写"，用户数据按身份天然隔离；服务端读取统一按用户身份收敛；
- **内容安全**：站外来源链接仅作溯源展示，不提供跳转；生成内容明确标注"AI 演绎"。

## 9. 常见问题速答（FAQ）

**Q1：换手机数据会丢吗？**
不会。衣橱、收藏、档案全部存于云端（微信云开发），换设备登录即恢复。

**Q2：推荐会过时吗？比如秋天还推荐夏装？**
不会。推荐由当日实时气温驱动，温度档变化当天生效；不合时宜的单品在推荐前已被过滤。

**Q3：效果图上的衣服是我那件吗？**
上装与下装以您的平拍图为参考参与生成，版型颜色高度还原；帽/鞋/包等配饰以文字描述辅助生成，偶有缺漏属模型能力边界，结构性升级已在规划中。

**Q4：AI 识别错了怎么办？**
识别结果只进预览页，每件单品入库前均可手动修改；入库后也可随时编辑。系统不存在 AI 自动写库的路径。

**Q5：生成一张效果图要多久？**
约 30–60 秒；同一搭配重复生成命中缓存，即时返回且不重复计费。

**Q6：依赖的 AI 模型如果停服怎么办？**
所有模型名均为可配置项（环境变量），更换模型只需改配置、无需改代码；推荐链路有双供应商自动降级；关键生图模型选用开源权重，具备跨平台迁移能力。

**Q7：一个月要花多少钱？**
出图有月度额度上限，成本封顶约 ¥12/月；正常日用约 ¥6–8/月。所有外部服务密钥与额度均有监控与闸门。
