# ADR-0018 · 演绎用两趟生图（pass1 主体 + pass2 配饰），而非一趟画完

- 状态：采纳（2026-09-21）
- 关联：ADR-0003（可插拔 provider）、ADR-0004（按需生图 + 额度）、ADR-0009（单品实物图必须进链路）、CONTEXT ③.5（云函数 60s 硬上限）、铁律「输入即键」

## 背景

「演绎」= 点「演绎」按钮后，把**你实拍的单品图**作为参考，在**你上传的人像参考照**上重新呈现整套搭配。当前固定走阿里云百炼（DashScope）`qwen-image-3.0`（通义万相 / qwen-image 系列，见 ADR-0003 与 README「演绎」一节）。

一个绕不开的工程现实是：**微信云函数 `config.json timeout:60` 是平台死线，无法抬升**。而「把人 + 全套衣服 + 鞋帽包画进同一张图」这件事，在这条链路上天然和三个硬约束冲突：

1. **保真**：视觉模型在「人 + 多件衣服 + 配饰」同框时，注意力被主体吸走，配饰最易被「吃掉 / 画错」（实证：渔夫帽被画成鸭舌帽、鞋整只消失）。
2. **60s 死线**：一趟高质量生图逼近 60s 会被 `-504003` 掐断，整张废、钱白花。
3. **缓存盐（铁律「输入即键」）**：同输入恒同缓存键——若一趟**偶发**丢一件，这张残图会被永久吐出（偶发 → 固化）。

一趟生图看上去省一步，实则会同时踩中「画错、超时、白花钱、偶发被钉死」四个坑。本 ADR 记录**为什么拆成两趟**以及两趟的具体契约。

## 决策

演绎出图固定走**两趟串行渲染**：

- **pass1（人衣主体）**：以人像参考照为底，画「上装 / 下装 / 连衣裙 + 人」的主体骨架，把姿态、体型、主色钉死。
- **pass2（配饰叠加）**：以 pass1 成品为基底，**只往上叠 ≤2 件有实拍图的配饰**（优先级 鞋 > 帽 > 包），保持人像与主体不变，只加配饰。

两趟**各自独立缓存键**（`key` / `p2Key`），主体稳定命中缓存，配饰那趟可独立重试。

## 为什么不是一趟

| # | 动因 | 一趟的失败模式 | 两趟的解法 |
|---|---|---|---|
| 1 | 保真 | 配饰被主体注意力挤掉、画错/消失 | pass1 钉死主体；pass2 只管配饰、姿态不变 |
| 2 | 60s 硬上限 | 逼近 60s 被 `-504003` 掐断，整张废 | pass1 后写**检查点**，pass2 被秒杀可只重跑 pass2 |
| 3 | 成本闸 | 跑前无法预估「要不要为凑齐配饰作废整张」 | pass2 只估配饰开销；预算不足直接跳过 pass2，主体仍可用 |
| 4 | 缓存盐 | 同键偶发丢件 → 残图被永久固化 | 主体/配饰解耦，配饰趟独立重试（重试必须变键） |

## 可靠性机制（检查点 + 补生成）

pass1 出图成功后立即写检查点：

```
stage: 'pass1-done'
pass1FileID: <云存储 fileID>
pass2 plan: <落任务文档，记录要叠哪 ≤2 件配饰>
```

第二趟若被 60s 硬杀，前端据「此态持续 > `PASS2_STALL_MS`(=62s，比平台 60s 上限更久 ⇒ 实例必死)」弹「补生成」按钮，**只重跑 pass2**（`action:'pass2'`，plan 从任务文档回读），复用 pass1 成品——仅花 pass2 的钱，pass1 不重复。

> 判据必须是「停滞 > 60s」而非「一见 pass1-done 就重跑」：后者会与正常在跑的第二趟撞车、重复花 pass2 的钱。

分辨率降到 `640*1120` 后 pass1+pass2 ≈ 40s，预算闸（`PASS2_BUDGET_MS=30000`，**预估式**判据 `已花 + 预估 > 预算`）几乎恒放行；冷跑若仍超预算，直接跳过 pass2，主体图照常可用。

## 保真边界（配饰资格漏斗）

pass2 取件资格：`ACCESSORY_ELIGIBLE=['帽子','鞋','包']` + 类目归一为「鞋」+ `pickItemImage` 非空（有实拍图）。

**没实拍图的配饰根本不进 pass2**——否则模型会凭空编鞋 / 包样式，直接破坏「图上衣服 = 你衣橱里那件」的保真承诺（ADR-0009）。这也是「3 图硬上限」（每套最多 pass1 + pass2 两次生图）与两趟独立缓存键的由来。

## 影响与代价

- **实现复杂度上移**：pass1 须写检查点、pass2 须读 plan 回放、前端须有「补生成」按钮与停滞判据——串行链路是**结构性**约束，不是偷懒。
- **成本**：每套最多 2 次生图调用（pass1 + pass2），但检查点让偶发失败只重花 pass2 的钱，而非整张重来。
- **门**：须有覆盖「pass1-done 停滞判据」「pass2 资格漏斗」「预算闸跳过 pass2」的单测 / e2e，防止「偶尔光脚」「补生成重复扣费」回归。
- 本决策**不引入**「旧试穿」概念（早期专用试穿模型已于 2026-09-10 退役，无替代）；演绎一律是「单品实拍图作参考、在参考照上重绘」，与 ADR-0009 的保真底线一致。
