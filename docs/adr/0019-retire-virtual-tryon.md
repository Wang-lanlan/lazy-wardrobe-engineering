# 0019：退役虚拟试衣（aitryon）路线

- 状态：已采纳（2026-09-10 入口退役；2026-09-17 链路清理随模型换代一并完成）
- 关联一手记录：`docs/tickets/0008-model-lifecycle-migration/`（原始仓；按公开边界 `docs/tickets/` 不纳入本仓）

## 背景
推荐页原本有「试衣 + 演绎」双按钮。试衣走阿里云百炼 `aitryon` 专用试衣模型，演绎走生图模型把已有单品图当参考合成上身效果。

## 决策
2026-09-10 起，推荐页收回单按钮「演绎」，试衣入口退役；保真诉求改由演绎链路承担。

## 理由（两条独立判据，任一即足够判死刑）
1. **覆盖率结构性不足**：`aitryon` 接口只有 top + bottom 两个槽位，而一套搭配按设计最多 7 件（内搭×2 + 外套 + 下装 + 鞋 + 包 + 配饰），画面至多覆盖约 1/3；外套占主槽会把叠穿内搭整体挤出。用户诉求是「整套级」答案（看这身能不能出门），2/7 的覆盖率靠迁移或调参救不回——连后续选用的 `qwen-image-3.0` 参考图上限也仅 3 张。
2. **死链**：`aitryon` 与 `aitryon-plus` 已列入阿里云百炼 **2026-10-10 下线清单**，且无对等专用试衣模型可换；不减，30 天后必报错。

> 关键澄清：退役**并非**因保真度不达标——真机反馈中「衣服不像」不在抱怨清单，保真度是兑现的。它死在「覆盖不了整身」+「官方要下线且无替代」这两个产品/平台层事实。

## 后果
- 入口为纯前端，重编译即验；链路清理搭 model-lifecycle 那次云函数部署的便车（`tickets/0008-02`），零额外部署成本。
- 失效守卫 `e2e-aitryon.js` / `aitryon.test.js` 一并删除——留下的守卫比没有更危险（会撒谎：mock 全绿、真机必 500）。
