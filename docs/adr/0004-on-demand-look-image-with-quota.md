# ADR 0004：上身图按需触发 + 组合缓存 + 月额度，且绝不弹扣费确认

- **日期**：2026-08-30
- **状态**：已接受
- **相关**：ADR 0003（成本基线）、ADR 0005（缓存键定义）

---

## 背景

上身图是本产品**唯一花钱**的功能。技术问题（多少钱一张）好解决，真正的敌人是**心理成本**：

> 每次点击都在花钱 → 用户不敢点 → 功能等于废掉。

使用者的原话是："为什么生成上身图需要花钱，成本太高体验感会下降。"

所以目标不是"把价格压到最低"，而是**让用户感知不到成本的存在**。

## 决策

三条硬规则：

**1. 按需触发，绝不自动生成**
方案默认展示**拼贴**（所引用单品横向排列），零成本、秒出。只有用户主动点「看上身效果」才触发生成与计费。不点即永远零成本。

**2. 绝不弹按次扣费确认**
点下去立刻开始生成，不打断。
*理由*：那种"本次将扣费 0.5 元，是否继续"的弹窗是焦虑的来源——它把每一次好奇都变成一次消费决策。宁可在别处控制成本，也不在操作路径上拦人。

**3. 额度条代替弹窗**
设置页常驻显示"本月 N / 30 张"，成本**可见、可控**，但不在操作路径上。

**配套护栏**：
- **组合缓存**：同一组合永久复用，命中即秒开且不扣费
- **月额度上限**：超出后停止生成，下月自动重置（防手滑、防异常循环）
- **命中缓存要明确告知**：提示"已生成过，本次不扣费"，让"复用不花钱"这件事被感知到

## 取舍

**放弃的**：

- 每次扣费前的显式确认（安全，但杀死体验）
- 无限生成（被月上限约束）

**换来的**：

- 用户敢点、愿意用
- 三重护栏下，实际月支出 0–3 元，比一顿早餐低
- 成本可见但无感

**为什么"不弹确认"的风险可接受**：最坏情况是手滑多点几次，被月上限和组合缓存兜住，单月损失封顶在几元。用几元的上限换掉持续的心理摩擦，这笔交易是划算的。

## 何时重开

- 使用者仍然不敢点（心理成本没消除）→ 说明额度条不够，考虑改为"月度预算进度条 + 预估金额"
- 月额度频繁触顶 → 说明按需触发不够，上调 `MONTHLY_LIMIT` 或重新审视成本
- 出现"点了却没出图但扣了费"的反馈 → 必须改：失败不应计费（当前实现中失败在写额度之前返回，符合预期，改动时勿破坏此顺序）
