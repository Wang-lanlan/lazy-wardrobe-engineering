# ADR 0015: 上传抠图升级——色键失败后走 AI 绿幕重绘再色键

日期：2026-09-09 ｜ 状态：**已被 ADR-0016 取代**（2026-09-10，历史留档）

> ⚠️ **本方案整体作废，勿照此实施。** 2026-09-10 用户拍板改用腾讯云数据万象 GoodsMatting
> 真抠图（ADR-0016），客户端色键与百炼绿幕重绘链路整体退役。本文保留为历史留档，
> 记录「为什么一度排除了 GoodsMatting」。需注意：
> ① 下方 GoodsMatting 的「0.01 元/次」**是对的**（2023-12-01 调价后实际价；0.14 元/次是调价前旧价）；
> ② 据此得出的「接入风险高于收益」结论已被推翻（真正的风险在本文选的生成式重绘上）。

## 背景

上传页抠图（spec 0006 T06）用客户端色键（边缘采样 + Chebyshev 阈值），纯色背景效果稳定，
但复杂背景（白衬衫白墙、阴影、杂色）效果差——coverage 落在正常区间的半透明结果
直接出图，难图只能回退原图。调研结论：纯色距离的天花板是算法层的，调阈值救不了。

## 决策

三级降级架构，色键仍是第一级：

```
纯色背景图 → 色键直抠（0 成本，毫秒级）          ← 大头
  ↓ shouldFallback 判失败（现有插槽）
难图 → 阿里云百炼 wanx2.1-imageedit 指令编辑
        「将背景替换为纯绿色绿幕 #00FF00」（0.14 元/张，新账号 500 张免费额度）
        → 绿幕图 → 现有色键抠绿幕（绿幕与常规衣物色距远，接近 100% 可靠）
  ↓ AI 也失败（网络/额度耗尽）
原图继续（现有 M1 兜底，不变）
```

核心思路：**AI 不负责抠图（生成模型无 alpha 通道），只负责把「难抠的背景」规整成
「色键最擅长的纯色」**——色键算法零改动，天然规避能力边界。
背景色选绿幕而非纯白：白色衣物在纯白底会被色键误抠（|Δ|≤30 内），绿幕（#00FF00）
与任何常规衣物颜色距离都远（军绿也差 176），是影视行业标准做法。

## 备选被拒

- **腾讯云数据万象 GoodsMatting**（0.01 元/次——2023-12-01 调价后实际价，本文原写即正确；电商级真抠图）：
  当时判断「与微信云开发存储跨账号体系，COS 绑定/detect-url 时效需实测，接入风险高于收益；
  保留为未来备选」。—— **该结论已于 2026-09-10 被推翻**：detect-url 模式让 COS 桶可保持空置、
  微信云存储仍是唯一真源；时效只需「拿到临时链接即用」即可规避。最终即采纳此方案（ADR-0016）。
- **remove.bg**：效果顶级但订阅贵（$9/月起），自用不划算。
- **rembg 自托管**（开源 BiRefNet/U2-Net）：onnxruntime 原生库 + 模型（u2net 170MB、
  BiRefNet 900MB+）远超微信云函数包体上限，且无外置服务器。
- **硅基流动直连**：标准模型广场无背景移除/图像编辑模型（已核实 2026-09）。
- **Qwen-Image-Edit（硅基流动 0.3 元/张）**：白底重绘同构可行但无免费额度，被
  wanx2.1-imageedit（0.14 元 + 500 张免费）覆盖。

## 后果

- 新增凭证：阿里云百炼 API Key → 云函数环境变量 `DASHSCOPE_API_KEY`（新账号 500 张
  免费额度内 0 成本；用尽后 0.14 元/张，只花在色键失败的难图上）。
- 新增云函数（AI 白底重绘）：接口形态仿 recognizeItem v4——start（提交任务）/poll
  （轮询结果）双段，规避客户端 3s 硬超时；imageedit 本身是异步任务。
- 费用护栏：每张图 AI 重绘**最多尝试 1 次**（重试不重复计费）；百炼报欠费/额度耗尽
  → 直接走原图兜底，不再重试。
- 状态机不动：AI 重绘发生在 `bg-removing` 环节内部（页面标记 `_aiTried`），
  `markBgFailed` 语义不变——AI 也失败才算失败。
- 免费额度属地华北2（北京）——API Key 需北京地域；免费政策随账号/时间可能调整，
  以百炼控制台资源包页为准。
