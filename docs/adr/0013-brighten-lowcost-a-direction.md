# ADR-0013 · 亮调阶段采用低成本 A 方向，延后 B/C 高成本方向

- 状态：采纳（2026-09-05，grill-with-docs 烤透）
- 关联：docs/specs/0002-brighten-proposal.md（试衣 T11 + 溯源 T12）

## 背景
清块阶段代码已全绿（0001 路线图 + T02 体检），进入"特色做到最高"的亮调设计。
试衣（T11）与溯源（T12）各有两个高成本候选被放弃：
- 试衣 B「自己vs参考图对比」需预置模特素材图（资产工作）；C「试衣图里换单品」每次交互一次 aitryon 调用 + 受 plus 模型叠穿只 1 槽限制。
- 溯源 C「风格雷达图」需算风格权重；A「30天时间线」需历史聚合。

## 决策
两条亮调均选**最低成本、可立即落地**的 A 方向，且**零新增模型调用、零新增素材资产**：
- 试衣 A = 博主签名+文案（图下方文字，懒懒自动写，复用 provenance + 现有 LLM 调用）
- 溯源 A = 收藏页加「跟博主学的 / 通用推荐」筛选栏（复用 provenance 过滤，零新计算）

B/C 方向全部 defer。

## 理由（trade-off）
1. **成本**：A 只在文案层/UI 筛选层动手，不碰图片合成、不追加模型调用、不需资产；B/C 任一项都要新工序或新算力。
2. **节奏**：项目是体验版自用，先跑通"溯源可见"比"惊艳但重"更值；A 当周可上真机，B/C 要排期。
3. **数据已就绪**：provenance 已落地（T05/T07 已绿），A 方向直接消费现成数据，不依赖任何未决项（B 对比依赖素材、C 换单品依赖 T03 plus 决策）。

## 后果
- 正面：亮调当周可见、零额外运营成本；与"输入即键/诚实降级"等铁律不冲突。
- 负面 / 风险：
  - 试衣懒懒文案走 A 自动写，可能有"AI 味"、不够人味 → 升级路径 = C 半自动（用户定语气模板，AI 套填）。
  - 若 provenance 覆盖率低，试衣多显「通用」、溯源"跟博主学的"栏偏空 → 先真机看覆盖率，再决定是否提 aiRecommend 案例注入率（T05/T14 已绿）。
- 可逆性：本决策是 UI 文案 + 筛选，易改；但"先 A 后 B/C"的产品站位未来读者可能疑问，故立此 ADR。

## 反证 / 不选的
- 不选试衣 B/C、溯源 C/A：非因为不好，而是成本/依赖不匹配"先跑通"的当前目标；B/C 作为明确 defer 项，覆盖率与质感达标后可单独立项。

成本收益结论不变（零新增模型调用的措辞未破）。
