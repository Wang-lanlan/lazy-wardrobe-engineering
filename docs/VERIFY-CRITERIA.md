# VERIFY-CRITERIA · 各验证阶段的通过判据

> **本文回答一个问题**：再验证时，出现什么结果，才能说「这套方法论是可行的」？
>
> 本文只写判据，**不写成功案例**。凡是判不出「通过 / 否决」的条目，一律显式标为「未知」——
> 空白本身是诚实，编一条成功案例才是失真。
>
> 本文受本仓两条既有纪律约束：① `CONTEXT.md` ③.4「不写聚合数字」（断言数会漂移）；
> ② METHODOLOGY §2.5「聚合数值不可验收」（`brain.cases=16` 骗局）。

---

## 0. 两条元判据（先于一切阶段）

任何阶段的判据，先要满足这两条，否则它不叫判据：

1. **外部可判定性**：一个没参与开发的人，只看仓库 + 跑命令，能否独立得出同一结论。
   若某条判据只有作者本人能判定，那它不是判据，是自述。
2. **不接受聚合数字**：`3/3 绿`、`41 门全绿`、`断言 200 条`这类都不能作为证据——
   数量会随维护漂移，且聚合值掩盖分布（见 §2.5 事故）。证据必须落到
   **「哪条主张、被哪道门、短路哪一行会红」**。

## 1. 阶段判据表

| 阶段 | 通过 | 可疑（需说明后才能算通过） | 否决 | 否决说明什么 |
|---|---|---|---|---|
| **0 对齐对象** | `git ls-remote` 的 sha 与待评估那份逐字相同；能列出跟踪文件清单 | 只有文档、无任何可执行物（此时只能评"文档自洽"，不能评"方法论"） | sha 对不上；或 clone 后 import 即断 | 你评的不是它 —— 后续所有阶段作废 |
| **1 门可跑** | 退出码 0，**且每道门能说出它守什么**（判据写在门里，不写在文档里） | 有门不打印它守的条件，只打印 `PASS` | 门不存在 / 空断言 / 断言恒真 | 「自包含可跑」是假的 |
| **2 门可红**（核心） | 关键路径逐条：**把被守护的条件短路回旧写法 → 相关门必转红 → 还原后复绿** | 短路了，但转红的门与短路点不对应（红错了地方） | **短路后仍然绿** | 该门是装饰品；它声称守的东西没有任何保护 |
| **3 等价性** | 行为不变的重构/迁移：**原有门一行未改即全绿** | 改了断言，但改动处注明「为何等价」且无契约变更 | 为了让它绿而改断言，且无契约变更记录 | 那不是等价变换，是偷偷换了契约 |
| **4 决策对账** | 每条决策能填满三格：**当前前提 / 失效信号 / 推翻后怎么办** | 填了，但前提是事后追认的（写不出当时的代价对照） | 某条决策**说不出它在什么条件下会变错** | 它不是决策，是信念 |
| **5 后验指标** | 至少一类事故的**复发序数在新门上线后停止增长** | 有拦截记录，但无「门上线日期 + 复发计数」两列 | 新门上线后，同类事故仍复发且序数继续 +1 | 门选错了条件 —— 这是全流程信息量最大的信号 |
| **6 边界自查** | 作者能说清「公开层可见的判据是哪几条」 | — | 用私有层的证明力去撑公开层的结论 | 证明力被夸大，属举证不实 |

## 2. 三档是什么意思

- **通过**：这一阶段的结论可以被外人独立复现。可以不完美（比如关键路径只覆盖部分门），
  但**不允许含糊**——含糊的"通过"等于否决。
- **可疑**：不是失败，是**要求补一句解释**才能计入。补不出解释 → 降为否决。
- **否决**：出现即说明该阶段不成立，且**归因是确定的**（见最后一列）。
  否决的价值高于通过：它直接指出哪条纪律没生效。

---

## 3. 「方法论可行」的最小判定

需要**两条相互独立的证据同时成立**：

1. **设计侧**：关键路径 100% 可短路转红。
   —— 注意判据是「关键路径」而非「全部门」。要求全部门都可红既不现实，也会诱使人
   为凑数写无意义的短路项。
2. **时间侧**：至少一类事故的复发曲线，在新门上线后**停止增长**。

单有任一条都不够，且失方向相反：

| 只有 | 你得到了 | 你仍然不知道 | 失败形态 |
|---|---|---|---|
| 设计侧（门能红） | 一批有效门 | 它们挡住了什么**真实损失** | 可能全是自嗨：门守的是假想风险 |
| 时间侧（复发停了） | 损失被挡住了 | 是**哪条纪律**挡的 | 无法复制到别处，方法论退化成运气 |

**推论**：任何只展示其中一侧的「方法论有效性」论证，都不成立。

## 4. 判「不可行 / 不可判定」的信号清单

出现任一，就**不能**声称方法论可行：

1. 短路判据后门仍绿。
2. 为了门绿而修改断言，且未记录契约变更。
3. 同类事故在门上线后仍复发，复发序数继续 +1。
4. 新主张持续增加，但「失效条件」一栏始终空白。
5. **判据需要作者在场才能判定**（外部人跑同样的命令得不出同一结论）。
6. 只能用聚合数字举证（`N/N 绿`、`断言 X 条`、`覆盖率 Y%`）。

第 5、6 条最容易被忽略：它们是**元层面的否决**——一旦成立，前面所有"通过"都不能被采信。

---

## 5. 进度度量：可证伪率

```
可证伪率 = 有「短路即转红」记录的主张数 / 已明确成文的主张数
```

选它当核心度量的理由：它同时要求两件事——
主张**必须先被明确成文**（否则无从短路），且它**真的可被否证**。

读法：

- 数值低不丢人（说明还有多少条停在"信念"层），**空白才丢人**。
- 真正该看的是**趋势**：「说出失效条件」的条目在增长，还是「未知」条目在增长。
  未知清单持续增长 ⇒ 方法论停在叙事层面，尚未成为纪律。

## 6. 未知清单（诚实空白，核对时逐条填）

| 主张 | 关键路径？ | 有短路转红记录？ | 失效条件是否写明？ |
|---|---|---|---|
| 铁律① 输入即键 | 是 | 部分（渲染缓存键域） | 待补 |
| 铁律② 诚实降级 | 是 | **未知** | 待补 |
| 铁律③ 代码校验替代自觉 | 是 | 部分（双闸/白名单） | 待补 |
| 铁律④ 自证 | 是 | **未知** | 待补 |
| 铁律⑤ 词表归一化 | 是 | 部分（真数据守卫） | 待补 |
| 铁律⑥ 部署了才算改了 | 是 | **未知** | 待补 |
| 铁律⑦ 失败路径有退路 | 是 | 部分（上传队列状态机） | 待补 |
| 铁律⑧ 纯函数优先 | 是 | **未知** | 待补 |

> 填表纪律：**填不出就写「未知」，不要写"待验证"**。
> "未知"是事实，"待验证"是掩盖——后者会被下次核对当成已有进度。
> 判定某条原则是否真被守住，只有一个操作判据：**有没有一道门，短路它必转红。**
> 没有 = 信念，而非纪律。

## 7. 复验节奏建议

| 时机 | 动作 | 产出 |
|---|---|---|
| 每次改动关键路径 | 跑该路径的短路项，逐轮跑 | 转红记录（不转红即修门） |
| 每次事故 | 台账追加一行：门上线日期 / 复发计数 | 复发曲线 |
| 换季 / 月度 | 重跑 §1 全表 + 更新 §6 未知清单 | 可证伪率趋势 |
