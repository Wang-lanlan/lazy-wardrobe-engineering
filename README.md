# 懒懒 OOTD（懒懒衣橱）· 小程序工程与方法论

> 本仓库**不开源业务大脑**（推荐 prompt、案例库、个人画像），只开源**工程方法论**：18 条 ADR、平台硬限制清单、测试门骨架与演示门、事故复盘。衣橱只是案例外壳，方法论才是资产。

👉 **30 秒自测**：clone 后执行 `node dev/demo-gates/run.js`，看到 `3/3 PASS` 即证明这套方法论可复现（零依赖，无需 `npm install`）。更完整的验证与边界说明见下方「⚠️ 实操边界」。

## 这是什么：懒懒 OOTD

懒懒 OOTD 是一个**个人自用的微信小程序**（体验版，不送审、不发布），帮**一个人、每一天、用已有的衣服**，收敛出 **3 套能直接出门的穿搭**。

- **输入**：电子衣橱（单品 + 实拍图）＋ 当天天气（高德）＋ 身形 / 肤色 / 雷区 / 偏好（穿搭档案）
- **输出**：每天 3 套 AI 推荐方案，由人格「懒懒」以轻松治愈系口吻给出
- **推荐依据**：**韩系灵感案例库**（韩国博主案例 + 结构化硬约束）——经双闸筛选注入；**真穿出该案例的硬约束才署名**，凑不齐就诚实降级、绝不硬凑。案例库内容不公开。
- **演绎**：点「演绎」按钮，把方案**渲染成上身效果图**——以单品实拍图为参考，让「图上的衣服 = 你衣橱里那件」
- **链路分工**：AI 推荐走云开发 AI+（DeepSeek）；**演绎出图走阿里云百炼（DashScope）视觉生成模型**

> 为什么不做发布版：个人主体小程序无法申请「深度合成」类目，且赛道小、单位经济不成立。本项目定位是**工程实证**，不是产品上线（见 `docs/公开方案-可执行.md`）。

## 演绎（上身效果图）是怎么生成的

「演绎」不是让模型凭空画衣服，而是把**你实拍的单品图**喂给视觉模型，在**你上传的参考照**人像上重新呈现这套搭配：

1. **模型**：默认 **`qwen-image-3.0`**（通义万相 / qwen-image 系列，阿里云百炼视觉生成模型），经 `WANX_KEY` 鉴权，调用方写死 `provider:'wanx'`。
2. **两趟渲染**：pass1 画人衣主体 → pass2 以产出为基底、只叠加 ≤2 件有实拍图的配饰（鞋 > 帽 > 包），保持基底只加配饰。拆两趟是为把最难保真的配饰单独出、不被主体「挤没」，且 pass1 后写检查点可在超时时只补跑 pass2（详见 `docs/adr/0018-two-pass-render.md`）。
3. **保真约束**：单品实拍图作为参考图进入生成，让「图上衣服 = 衣橱那件」；覆盖率用视觉模型逐件自证（worn / present / missing 三态）。
4. **缓存与版本盐**：同组合 + 同模型 + 同参考图永久复用；改 prompt / 模型 / 换人像底图都会自动换缓存键（铁律「输入即键」）。
5. **成本**：按张计费、不点不生成；单价与月费见下方「[费用](#费用)」一节（拼贴展示零成本）。

> 系统 pluggable 支持硅基流动（默认 Qwen-Image-Edit / Z-Image-Turbo）与混元作为备选生图链路；但**推荐页「演绎」按钮固定走百炼**。

## 第 1 步：填 AppID

用微信开发者工具打开 `wardrobe-miniapp` 文件夹，右上角「详情」→「基本信息」→ 把 AppID 改成你的。
（或直接改 `project.config.json` 里的 `appid` 字段）

## 第 2 步：开通云开发

1. 开发者工具顶部工具栏点「云开发」
2. 新建环境，名称随便（比如 `wardrobe`），**选按量付费 / 免费额度即可**
3. 建好后复制**环境 ID**（形如 `wardrobe-1x2y3z`）
4. 打开 `app.js`，把 `YOUR_CLOUD_ENV_ID` 换成它

## 第 3 步：建 4 个数据库集合

云开发控制台 → 数据库 → 新建集合，依次建这 4 个：

| 集合名 | 用途 |
|---|---|
| `items` | 单品 |
| `meta` | 穿搭档案、参考照、额度 |
| `looks` | 收藏的方案 |
| `genCache` | 已生成上身图的缓存（同组合不重复扣费）；**天气缓存也存这里**（固定 id `weather`，不进 `meta`） |

每个集合建好后，点「权限设置」→ 选 **「仅创建者可读写」**（我们是单人自用，这个最安全）。

## 第 4 步：上传并配置云函数

对下面 7 个云函数，**逐个右键 →「上传并部署：云端安装依赖」**：

| 云函数 | 需要配置的环境变量 |
|---|---|
| `aiRecommend` | 无（走云开发 AI+，不用额外 key） |
| `genLookImage` | 见下表 |
| `getWeather` | `AMAP_KEY` = 你的高德 key |
| `seedImport` | 无 |
| `exportData` | 无 |
| `mattingGoods` | `COS_SECRET_ID` / `COS_SECRET_KEY` / `COS_BUCKET` / `COS_REGION`（腾讯云 COS，加衣抠图结果回存用） |
| `recognizeItem` | `SILICONFLOW_KEY` + `SF_VL_MODELS`（加衣时商品识别读图）⚠️ 它**没有默认 config.json**，见下方超时说明 |

### genLookImage 的环境变量（云开发控制台 → 云函数 → 配置 → 环境变量）

| 变量 | 值 | 说明 |
|---|---|---|
| `SILICONFLOW_KEY` | 你的硅基流动 key | 必需 |
| `SF_I2I_MODEL` | `Qwen/Qwen-Image-Edit-2509` | 有参考照时用（图生图） |
| `SF_T2I_MODEL` | `Tongyi-MAI/Z-Image-Turbo` | 没参考照时用（文生图，$0.005/张） |
| `IMG_PROVIDER` | `siliconflow` | 换链路时改这个 |
| `MONTHLY_LIMIT` | `60` | 每月生成上限，防手滑。⚠️ 改它要同步 `pages/profile/profile.js` 顶部的同名常量，否则档案页显示的「已用 X / 上限」会和云函数判定对不上 |
| `WANX_KEY` | 你的阿里云百炼（DashScope）key | **「演绎」出图必需**——推荐页「演绎」按钮按调用显式传 `provider:'wanx'` 走百炼 |

> 注意：Z-Image-Turbo 是**纯文生图**模型，传参考图会报错；有参考照时必须用 Qwen-Image-Edit 系列。代码已自动按「有无参考照」选择模型，你不用管。

> ⚠️ **别忘了把执行超时改成 60 秒**（就在环境变量同一个「配置」页里，默认是 3 秒）。`genLookImage`、`aiRecommend`、**`recognizeItem`** 都要改——其中 `recognizeItem` 没有默认 `config.json`，必须自己**新建**一个并把超时设 60 秒，否则商品识别读图会被 3 秒默认超时掐断。

> **生图渠道**由云函数校验，白名单只有三个：`siliconflow`（默认；无参考照 ¥0.036/张、有参考照 ¥0.10/张）｜`wanx`（阿里云百炼 `qwen-image-3.0`，单张 **¥0.24**；一次演绎两趟 ≈ **¥0.48**，需 `WANX_KEY`；明细见「[费用](#费用)」）｜`hunyuan`（云开发混元官方，¥0.5，不需要 key）。
> ⚠️ `IMG_PROVIDER` 只影响**未显式指定 provider 的调用方**——推荐页「演绎」按钮按调用写死 `provider:'wanx'`（与全局环境变量解耦），所以改 `IMG_PROVIDER` **不会**改变「演绎」走哪条链路。
>
> **演绎出图模型**：阿里云百炼（DashScope）视觉生成模型，默认 **`qwen-image-3.0`**（通义万相 / qwen-image 系列），由 `WANX_KEY` 鉴权。系统同时 pluggable 支持硅基流动（默认 Qwen-Image-Edit / Z-Image-Turbo）与混元作为备选生图链路，但「演绎」按钮固定走百炼。

## 常见问题

**Q：点「演绎」报错（生成上身效果图）**
A：云开发控制台 → 云函数 → `genLookImage` → 日志，看具体报错。常见三种：
- **model 不存在** →  SiliconFlow 会周期性上下架模型，去它官网 Models 页查当前可用名，填进 `SF_I2I_MODEL`
- **图生图被拒** → 换一个支持 I2I 的模型（如 `black-forest-labs/FLUX.1-Kontext-dev`）
- **key 没配 / 余额不足** → 检查 `SILICONFLOW_KEY` 和账户余额

改环境变量就行，代码是 pluggable 的，不用重新写业务代码。

**Q：AI 推荐报错 `AI 调用失败：Request failed with status code 42`**
A：这是**模型组名写错**导致的——`ai.createModel()` 的参数必须是 GroupName（如 `cloudbase`），不能写厂商名 `deepseek`。代码已修，重新上传 `aiRecommend` 云函数即可。

若仍失败，说明云开发 AI+ 侧还没就绪：**AI+ 默认不启用任何模型**，需去「云开发控制台 → AI → 模型服务」启用目标模型。
更省事的做法：给 `aiRecommend` 加一个环境变量 `SILICONFLOW_KEY`（填你在 `genLookImage` 上用过的同一个 key），推荐就会改走硅基流动，不再依赖 AI+。
注意环境变量是**按云函数隔离**的，两个函数要各配一次。

**Q：AI 推荐偶尔返回格式异常**
A：大模型偶尔输出不规整，点「换一批」重试即可。若频繁出现，看 `aiRecommend` 日志里的 `provider` 字段确认走的是哪条链路。

**Q：天气显示获取失败**
A：检查 `AMAP_KEY` 是否配好、是否选的「Web服务」类型。手机上要授权定位。

**Q：想省到底，完全不生成上身图**
A：不点「演绎」就永远 0 成本。拼贴展示是不花钱的。
