## 第 1 步：填 AppID

用微信开发者工具打开 `wardrobe-miniapp` 文件夹，右上角「详情」→「基本信息」→ 把 AppID 改成你的。
（或直接改 `project.config.json` 里的 `appid` 字段）

## 第 2 步：开通云开发

1. 开发者工具顶部工具栏点「云开发」
2. 新建环境，名称随便（比如 `wardrobe`），**选按量付费 / 免费额度即可**
3. 建好后复制**环境 ID**（形如 `wardrobe-1x2y3z`）
4. 打开 `app.js`，把 `YOUR_CLOUD_ENV_ID` 换成它

## 第 3 步：建 4 个数据库集合

云开发控制台 → 数据库 → 新建集合，依次建这 4 个：

| 集合名 | 用途 |
|---|---|
| `items` | 单品 |
| `meta` | 穿搭档案、参考照、额度、天气缓存 |
| `looks` | 收藏的方案 |
| `genCache` | 已生成上身图的缓存（同组合不重复扣费） |

每个集合建好后，点「权限设置」→ 选 **「仅创建者可读写」**（我们是单人自用，这个最安全）。

## 第 4 步：上传并配置云函数

对下面 5 个云函数，**逐个右键 →「上传并部署：云端安装依赖」**：

| 云函数 | 需要配置的环境变量 |
|---|---|
| `aiRecommend` | 无（走云开发 AI+，不用额外 key） |
| `genLookImage` | 见下表 |
| `getWeather` | `AMAP_KEY` = 你的高德 key |
| `seedImport` | 无 |
| `exportData` | 无 |

### genLookImage 的环境变量（云开发控制台 → 云函数 → 配置 → 环境变量）

| 变量 | 值 | 说明 |
|---|---|---|
| `SILICONFLOW_KEY` | 你的硅基流动 key | 必需 |
| `SF_I2I_MODEL` | `Qwen/Qwen-Image-Edit-2509` | 有参考照时用（图生图） |
| `SF_T2I_MODEL` | `Tongyi-MAI/Z-Image-Turbo` | 没参考照时用（文生图，$0.005/张） |
| `IMG_PROVIDER` | `siliconflow` | 换链路时改这个 |
| `MONTHLY_LIMIT` | `60` | 每月生成上限，防手滑。⚠️ 改它要同步 `pages/profile/profile.js` 顶部的同名常量，否则档案页显示的「已用 X / 上限」会和云函数判定对不上 |
| `WANX_KEY` | 你的阿里云百炼（DashScope）key | **「演绎」出图必需**——推荐页「演绎」按钮按调用显式传 `provider:'wanx'` 走百炼 |

> 注意：Z-Image-Turbo 是**纯文生图**模型，传参考图会报错；有参考照时必须用 Qwen-Image-Edit 系列。代码已自动按「有无参考照」选择模型，你不用管。

> ⚠️ **别忘了把执行超时改成 60 秒**（就在环境变量同一个「配置」页里，默认是 3 秒）。`genLookImage` 和 `aiRecommend` 都要改，否则 AI 没跑完就被掐断。

> **生图渠道**由云函数校验，白名单只有三个：`siliconflow`（默认；无参考照 ¥0.036/张、有参考照 ¥0.10/张）｜`wanx`（阿里云百炼，¥0.20，需 `WANX_KEY`）｜`hunyuan`（云开发混元官方，¥0.5，不需要 key）。
> ⚠️ `IMG_PROVIDER` 只影响**未显式指定 provider 的调用方**——推荐页「演绎」按钮按调用写死 `provider:'wanx'`（与全局环境变量解耦），所以改 `IMG_PROVIDER` **不会**改变「演绎」走哪条链路。

### 「试衣」（aitryon）已退役——保真诉求改由「演绎」承担

> **2026-09-10 决定并落地：直接删除。** 推荐页每套方案只剩一个「演绎」按钮；「试衣」入口与 aitryon 渠道均已移除。

退役原因（三条叠加，最后一条是决定性的）：

1. **覆盖率太低**：aitryon 接口只接受 `top` + `bottom` 两个槽位，而一套搭配按 spec 最多 7 件（内搭×2 + 外套 + 下装 + 鞋 + 包 + 配饰）→ 画面覆盖率约 2/6 ≈ 33%；且外套优先占 `top` 槽，会把叠穿的内搭整体挤掉。
2. **真机主因是「缺东西 + 太糙」**（2026-09-10 反馈）——而「衣服不像」并不在列，说明保真度其实是兑现的，问题出在整身完整性。
3. **30 天后必然报错的死链**：`aitryon` / `aitryon-plus` 已列入阿里云百炼 **2026-10-10 下线清单**，且**无对等专用试衣模型**可迁移。

处理方式与边界：

- **前端入口退役**：`docs/tickets/0008-model-lifecycle-migration/01-retire-tryon-entry.md`
- **云函数 aitryon 分支移除**：provider 白名单收为 `siliconflow | hunyuan | wanx`；再传 `aitryon` 会被**显式拒绝**（`不支持的生图渠道`），而不是静默回落到 siliconflow——静默换渠道会让「为什么图变了」无从归因。见同目录 `02-migrate-render-model.md`
- **保真（画面里是你的实拍单品，而非模型凭空画的衣服）改由「演绎」链路承担**：演绎把单品实拍图作为参考图喂给模型。
- **历史数据不受影响**：收藏页仍能显示旧方案里存过的试衣图（读的是数据库历史文档，与推荐页代码无关）。

云开发控制台 → 左侧「AI+」→ 开通（走免费额度即可）。`aiRecommend` 用它调 DeepSeek。

## 第 6 步：导入你的 54 件衣服

1. 编译运行，点底部 **「档案」** tab
2. 滑到最下面 → 点「**导入初始衣橱清单（54 件）**」
3. 提示新增/跳过数量就成功了（此操作幂等，重复点不会产生重复数据）

> **若导入后衣橱仍显示 0 件**：数据其实已写进库，但云函数写入的记录缺少归属人标记，前端查不到。需重新上传 `seedImport` 云函数（右键 →「上传并部署：云端安装依赖」）后再点一次导入。详见 `docs/SETUP.md` 坑位清单。

## 第 7 步：填档案 + 传参考照

档案页把身高体重、身形、肤色、雷区、想多穿填上（**这些直接决定推荐准不准**），然后上传那张参考照。

> 你可以直接填：身高 / 体重 / 身形 / 肤色，以及「穿什么显气色好」「雷区」「想多穿」。（占位示例：160cm / 50kg / 标准身形 / 中性肤色 / 雷区：露背装，荧光色 / 想多穿：长裤，紧身内搭——**占位示例，非真实档案**）

## 第 8 步：上传体验版

开发者工具右上角「上传」→ 填版本号和备注 → 上传完成后，去 mp.weixin.qq.com → 管理 → 版本管理 → 开发版本 会看到它 → 点「体验版二维码」→ 手机微信扫码，就能用了。

**体验版不用提审，长期有效，只有你（和你添加的体验成员）能用。**

## 日常使用

- **衣橱页**：筛选、搜索、长按卡片可编辑/收纳/删除；没照片的卡片上点「拍照」直接补图

## 常见问题

**Q：点「看上身效果」报错**
A：云开发控制台 → 云函数 → `genLookImage` → 日志，看具体报错。常见三种：
- **model 不存在** →  SiliconFlow 会周期性上下架模型，去它官网 Models 页查当前可用名，填进 `SF_I2I_MODEL`
- **图生图被拒** → 换一个支持 I2I 的模型（如 `black-forest-labs/FLUX.1-Kontext-dev`）
- **key 没配 / 余额不足** → 检查 `SILICONFLOW_KEY` 和账户余额

改环境变量就行，代码是 pluggable 的，不用重新写业务代码。

**Q：AI 推荐报错 `AI 调用失败：Request failed with status code 42`**
A：这是**模型组名写错**导致的——`ai.createModel()` 的参数必须是 GroupName（如 `cloudbase`），不能写厂商名 `deepseek`。代码已修，重新上传 `aiRecommend` 云函数即可。

若仍失败，说明云开发 AI+ 侧还没就绪：**AI+ 默认不启用任何模型**，需去「云开发控制台 → AI → 模型服务」启用目标模型。
更省事的做法：给 `aiRecommend` 加一个环境变量 `SILICONFLOW_KEY`（填你在 `genLookImage` 上用过的同一个 key），推荐就会改走硅基流动，不再依赖 AI+。
注意环境变量是**按云函数隔离**的，两个函数要各配一次。

**Q：AI 推荐偶尔返回格式异常**
A：大模型偶尔输出不规整，点「换一批」重试即可。若频繁出现，看 `aiRecommend` 日志里的 `provider` 字段确认走的是哪条链路。

**Q：天气显示获取失败**
A：检查 `AMAP_KEY` 是否配好、是否选的「Web服务」类型。手机上要授权定位。

**Q：想省到底，完全不生成上身图**
A：不点「看上身效果」就永远 0 成本。拼贴展示是不花钱的。
