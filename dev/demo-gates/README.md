# 自包含演示门（dev/demo-gates）

本目录是「懒懒衣橱」工程方法的**可运行证据**：clone 下来直接跑，全绿即证明工程纪律在。

```bash
node dev/demo-gates/run.js
```

退出码 `0` = 全绿；非 `0` = 有门转红（可直接接 CI）。

## 为什么是「演示门」而不是全部 40 门？

真实仓库有 40+ 道测试门（`node dev/run-gates.js`），但它们依赖私有大脑
（`cloudfunctions/`、`pages/`、`utils/`、案例库、个人画像）——按公开边界，这些**不公开**。
若把依赖私有模块的门直接搬来，clone 必是 broken import，反而破坏「可验证」这个最硬的优点。

所以这里只放**自包含、零业务依赖**的演示门：它们用示意数据复刻真实门的**纪律与判据**，
证明「这道门真的在守东西」，而不交出业务语义。要复刻全部 40 门，需拿到私有仓库。

## 三道门在守什么

| 门 | 守的纪律 | 对应真实事故 / 铁律 |
|---|---|---|
| `cacheKeyVersionSalt.test.js` | 缓存键必须含版本盐；输入即键 | 铁律①「输入即键」；`-504003` 后「云端升版被误判成旧版」第五次复发 |
| `fitRoundTrip.test.js` | fit 词表双端归一、幂等 | 铁律③「词表归一化」；同件衣服被当成两件 → 缓存分裂 |
| `budgetGatePreEstimation.test.js` | 预算闸必须「预估式」而非「事后式」 | `-504003`：串行两趟渲染撞 60s 平台硬墙 |

## 一道门该有的形状（给想抄的人）

1. 文件名 `*.test.js`，`node` 直跑，不引任何框架；
2. 用 Node 内置 `assert`，**断言失败就抛异常 → 进程退出码非 0**；
3. 门只验证「被守护的条件」——失效时静默给错结果、不报错，所以必须用反向验证证明它在守；
4. 顶部注释写清「为什么要有这道门」+「对应哪条铁律 / 哪次事故」。

> 想看「门没在守」长什么样：把某道门的判据短路回旧写法，期望它**必转红**，再还原。
> 这正是 `reverse-verify-new-gates` 那套做法——绿得可疑时，先证明它能红。
